# 04. 광고 배치 전략 (2026-10-07 수정본)

> **수정 이력**
>
> 초안에서는 "출시 후 4~8주는 광고 없음"을 권고했다. 하지만 아래 두 가지 이유로 **출시 때부터 약한 광고를 넣는 쪽으로 바꿨다.**
>
> 1. 광고가 없으면 Pro의 "광고 제거" 혜택이 의미가 없다.
> 2. 나중에 광고를 추가하면 기존 사용자의 반발 리뷰를 부른다.
>
> 시각 목업: claude.ai 캔버스 "Pageframe 광고 배치 목업"의 '광고 배치' 페이지 (①–⑥)

## 1. 결론

1. **출시 버전부터 무료 사용자에게 광고를 보여 준다.** 단, 작업을 막지 않는 위치에만 둔다.
2. **광고의 역할은 수익보다 "Pro로 가는 길"이다.**
   - 모든 광고 카드에 "Remove ads with Pro" 링크를 단다.
   - 무료 체험을 다 쓴 사용자에게는 보상형 광고로 결제 직전 단계에 붙잡아 둔다.
3. **전면 광고, 앱 시작 광고, 촬영·저장 흐름 안의 광고, 하단 배너는 넣지 않는다.** "No full-screen ads"는 CamScanner와 가장 확실히 구별되는 점이다.

## 2. 배치표

| 위치 | 형식 | 규칙 | 목업 |
|---|---|---|---|
| **홈 — 문서 목록 3번째 아래** | 네이티브 1개. 정지 이미지 우선, 동영상은 음소거·자동 재생 없음 | 문서가 3개 미만이면 목록 맨 끝에 둔다. 홈 최상단(검색창 아래)에는 두지 않는다. 카드 하단에 "Remove ads with Pro" | ② |
| **Tools 화면 — 섹션 사이** | 네이티브 1개 | 현재 위치(Edit images와 PDF tools 사이) 유지. 같은 링크 추가 | ④ |
| **무료 체험 소진 후 Pro 도구 화면** | 보상형 (사용자가 선택) | 주 버튼 "Upgrade to Pro", 보조 버튼 "Watch a short ad · 1 more use". 기능 묶음당 하루 1회 | ⑤ |
| 설치 후 첫 24시간 (또는 첫 세션) | 없음 | 광고 슬롯 자체를 숨긴다 | ③ |
| Pro 사용자 | 없음 | 현재 구현 유지 | – |
| 앱 시작, 카메라·검토·저장, 저장 후 전면, 하단 배너 | **절대 없음** | 저장 후 전면 광고 코드(`CompletionAdvertisement`)는 꺼진 상태(`completionAdEnabled: false`)를 유지한다 | – |

**"Remove ads with Pro" 링크를 누르면** 결제 화면이 **"No ads" 슬라이드부터** 열린다 (목업 ⑥).

## 3. 현재 구현과의 차이 (개발 작업)

| 항목 | 현재 | 바꿀 것 |
|---|---|---|
| 홈 광고 위치 | `HomeView`의 검색창 바로 아래, 영상, 화면의 약 25% | 문서 목록 3번째 아래로 이동. 정지 이미지 우선 요청, 높이 축소 |
| 광고 → Pro 연결 | 없음 | 광고 카드에 "Remove ads with Pro" → `PaywallView(feature: .noAds)` |
| 신규 사용자 보호 | 없음 | 설치 시각을 저장하고 24시간 동안 `HomeAdvertisementSlot`을 숨김 |
| 보상형 광고 | 없음 | `ProToolLockView`에 Rewarded 버튼 추가. 묶음별 하루 1회 카운터 |
| Release 빌드 광고 | 꺼짐 (`testAdsEnabled` false) | 실제 AdMob ID, UMP 동의, SKAdNetwork, 개인정보 라벨을 준비한 뒤 켠다 |
| 맞춤형 광고 | – | **비맞춤형으로 시작한다.** ATT 팝업 없이 IDFA를 요청하지 않는다. 개인정보 포지셔닝을 지키기 위해서다 |

## 4. 출시 전 체크리스트

- [ ] AdMob 실제 앱 ID, 네이티브·보상형 광고 단위 등록
- [ ] UMP 동의 메시지(EU·영국·스위스)와 설정의 "Privacy options" 진입점
- [ ] 비맞춤형 광고 요청 설정, ATT 요청 없음
- [ ] App Store 개인정보 라벨을 AdMob 수집 항목에 맞춰 작성. Google iOS 데이터 공개 가이드로 확인한다. "문서 내용은 광고 SDK에 전달되지 않음"은 앱 설명과 개인정보 화면에 명시한다
- [ ] SKAdNetwork 식별자 등록
- [ ] 공개 개인정보처리방침 URL
- [ ] 광고 콘텐츠 등급은 General 유지 (현재 `maxAdContentRating = .general`)
- [ ] 테스트 항목: 오프라인, 광고 없음(no fill), 구매·복원 직후 광고가 사라지는지, 작은 화면, 백그라운드

## 5. 수익 추정 (참고)

- **네이티브:** DAU 1,000명 × 하루 2회 노출 × 채움률 80% × eCPM $2 = 하루 약 $3.2, **월 약 $100**. 한국은 그 절반 정도다.
- **보상형:** DAU 1,000명 × 5% × 하루 1회 × eCPM $12 = 하루 약 $0.6, **월 약 $18**.
- 같은 규모의 구독 순매출은 월 $3,000–5,000 수준이다 (03 문서). 광고 수익 자체는 작다.
- **그래서 광고의 성과는 수익이 아니라 다음으로 측정한다.**
  - "Remove ads" 링크 탭 → 결제 전환율
  - 보상형 광고 시청 후 7일 안에 결제한 비율
  - 광고 노출 사용자와 비노출 사용자(첫 24시간)의 D7 유지율 차이
  - 리뷰에서 "광고"가 언급되는 비율

## 6. 단계 조정 기준

| 신호 | 조치 |
|---|---|
| 1·2점 리뷰에서 "광고"가 자주 언급됨 | 홈 광고를 빼고 Tools·보상형만 남긴다 |
| Remove ads 경로의 결제 전환이 거의 없음 | 광고 위치는 유지하되, 링크 문구와 디자인을 A/B 테스트한다 |
| DAU 5천 명 이상이고 리뷰가 안정적 | 문서 상세 화면 하단 등 추가 위치를 검토한다. 전면 광고는 여전히 넣지 않는다 |
